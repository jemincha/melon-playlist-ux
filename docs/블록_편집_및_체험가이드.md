# 블록 편집과 전후 비교 체험

## 이번 변경의 목적

기존 데모는 묶음 편집을 켜는 방법이 잘 드러나지 않았고, 묶음 안에서 곡의 순서를 바꿀 수 없었다. 기본 모형과 개선안도 직접 설명하지 않으면 차이를 파악하기 어려웠다.

## 편집 방식

- 개선안에서 편집을 시작하면 **아티스트 블록**이 기본으로 열린다.
- 아티스트 제목 옆 핸들과 ↑↓는 해당 블록의 모든 곡을 함께 이동한다. 블록 내부 순서는 유지한다.
- 곡 옆 핸들과 ↑↓는 **해당 블록 내부**의 순서를 바꾼다. 첫 곡의 위 이동, 마지막 곡의 아래 이동은 막는다.
- 다른 아티스트 구간으로 개별 곡을 옮기려면 **곡별 편집**으로 전환한다.
- 연속된 같은 아티스트의 곡을 하나의 블록으로 취급한다. 떨어진 구간을 임의로 합쳐 기존 흐름을 바꾸지 않는다.
- 두 수준의 드래그 영역은 별도의 DnD 컨텍스트로 구성한다. 마우스/터치 핸들 외에 키보드 Space → 방향키 → Space와 ↑↓ 버튼을 제공한다.
- 저장 전에 취소할 수 있고, 저장 후 이전 목록으로 되돌릴 수 있다.

## 처음 방문하는 사람의 체험

첫 방문에 곡 추가 버튼을 가리키는 코치마크로 시작한다. 완료/닫기 여부는 브라우저에 기록한다. 체험 진입은 **‘처음부터 체험하기’ 하나**로 통일했다. 기본/개선 선택 탭과 별도 초기화 버튼, 비교 단계의 독립 체험 버튼은 제거했다. 체험은 같은 224곡 예제로 초기화한다.

1. **기본 방식:** 곡 추가 → 한로로의 가상 신곡 ‘새벽 세 시’ → 맨 끝에 추가. 실제 결과인 225번째와 바로 앞 아티스트 cotoba를 보여준다.
2. **개선 방식:** 같은 원본 목록에서 같은 신곡을 다시 담는다. 사용자가 기존 한로로 구간을 선택하고, 217번째에 삽입된 결과를 확인한다. 기존 곡의 상대 순서를 유지한다.
3. **블록 편집:** 아티스트 블록과 내부 곡을 각각 이동해 본다. 실제 이동에 따라 완료 표시가 켜지고 변경을 저장한다.

각 단계마다 배경을 어둡게 덮고 실제 눌러야 할 요소에 테두리와 연결된 말풍선을 표시한다. 강조된 실제 버튼/라디오를 누르면 다음 단계로 진행한다. 곡 추가 → 담기 → 추가 확인, 개선 구간 선택 → 추가 확인, 편집 → 블록 아래 이동 → 곡 위 이동 → 저장으로 안내한다. 결과를 읽는 단계에만 ‘다음’을 표시한다. 마지막 ‘완료’ 이후에는 개선안을 자유롭게 사용할 수 있다.

코치마크는 바텀시트의 native dialog 안에서도 같은 최상위 레이어에 배치한다. 강조 대상 바깥 클릭을 막고, Tab 이동 범위를 대상과 코치마크 버튼으로 제한한다. × 또는 Escape로 중단할 수 있으며, 창 크기 변경과 스크롤에 맞춰 강조 위치를 다시 계산한다.

추가된 곡을 강조하고 해당 위치로 스크롤한다. 비교 숫자는 실행 결과에서 계산한다. 작업 시간 단축이나 이탈률 개선 같은 검증되지 않은 성과 수치는 제시하지 않는다.

## 검증

- 동일 신곡의 기본 모형 225번째 / 개선안 217번째 삽입을 브라우저에서 확인했다.
- Tuesday Beach Club 3곡을 블록 단위로 옮겨 모든 곡과 내부 순서가 유지되는지 확인했다.
- 블록 내부의 곡 순서 변경과 첫 곡의 위 이동 제한을 확인했다.
- 곡 핸들과 블록 핸들의 키보드 드래그를 각각 확인했다.
- 변경 저장 후 목록에 순서가 반영되는지 확인했다.

상세 편집 UI는 공개 자료를 참고한 재구성이다. 기본 모형은 최신 멜론 앱의 기능 전체를 재현하거나 기능 부재를 증명하는 자료가 아니다. 사용자 연구에서 체험 안내 없이도 두 핸들의 역할을 이해하는지, 블록 경계 제한이 자연스러운지 추가 확인해야 한다.
