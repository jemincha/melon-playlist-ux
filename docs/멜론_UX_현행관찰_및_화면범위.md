# 통합 목업 — 현행 관찰과 재현 화면 범위

작성일·공식 자료 재확인일: 2026-11-06
상태: 공식 자료 예비 조사 / 실제 모바일 앱 직접 관찰 미실시

## 1. 서비스별 예비 비교

아래는 동일 기기에서 실행한 사용성 비교가 아니다. 공식 설명, 검색 결과 확인, 직접 조작을 구분한다. ‘청취 기록 보존’은 사용자가 다시 찾는 재생 이력에 남는지의 뜻이며 정산·내부 로그 보존과 다르다.

| 서비스 | 공식 자료에서 확인한 것 | 기록 보존·반영 분리 판단 | 남은 직접 확인 |
|---|---|---|---|
| 멜론 | 공개 서비스 설명에서 음악서랍·추천 등 안내. 이번 취향 제어 기능은 미확인 | 없음으로 확정하지 않음 | 현재 앱의 개인화 제어·기록·플레이어·대기열 경로 전체 |
| Spotify | 곡·플레이리스트 취향 제외, 과거·향후 청취의 추천 영향 감소, 다시 포함하는 메뉴 안내 | 모든 기록 보존·모든 추천 신호 완전 차단을 보장하는 설명으로 해석하지 않음 | 제외 후 History 표시, 재생 출처별 차이, 플레이어 진입·복귀 경험 |
| Apple Music | 공식 검색 결과에서 Use Listening History 해제와 집중 모드 연계 설명 확인. 본문 직접 재조회는 429 | 기록을 보존하는 별도 학습 제외라고 단정하지 않음 | 실제 이력 노출·추천 영향·집중 모드 복귀와 OS별 경로 |
| YouTube Music | 기록 일시중지 시 해당 콘텐츠가 기록에 표시되지 않고 추천 개선에 사용되지 않음. YouTube와 설정 공유 | 기록 보존+학습 제외와 다른 동작임을 공식 설명으로 확인 | Android/iOS 실제 메뉴·복귀·계정별 노출 |

### 출처와 확인 한계

- [Spotify — Exclude a playlist or track from your taste profile](https://support.spotify.com/nz/article/exclude-playlists-or-tracks-from-your-taste-profile/): 본문 확인. 제외 반영에는 최대 48시간이 걸릴 수 있고 일부 추천은 더 늦게 반영될 수 있다고 안내한다. 제외 목록 밖에서 들은 같은 곡은 반영될 수 있으므로 출처 조건을 함께 기록한다.
- [Apple — Get personalized recommendations in Music on iPhone](https://support.apple.com/en-ca/guide/iphone/iph2b1748696/27/ios/27): 공식 도메인 검색 결과 확인, 직접 본문 요청은 429. 화면·상세 결과는 미확인이다.
- [YouTube Music — View, delete, or pause watch history](https://support.google.com/youtubemusic/answer/6364666?hl=en): 본문 확인. 기록 일시중지와 취향 학습만 제외하는 제안을 혼용하지 않는다.
- [멜론 App Store](https://apps.apple.com/kr/app/id415597317): 검색 결과의 서비스 설명만 참고. 버전 기록과 플랫폼별 노출이 섞여 있으므로 현행 버전을 확정하지 않는다.
- [멜론 Windows 순서 변경 FAQ](https://help.melon.com/web/faq/content.htm?faqId=2957): 본문 확인. 2023-08-29의 Windows 전용 정렬·다중 곡 이동 근거이며 최신 모바일 재현 근거가 아니다.

## 2. 실제 멜론 관찰의 최소 묶음

같은 OS·앱 버전·계정 조건에서 아래 경로를 하나의 연속 작업으로 관찰한다. 개인정보는 제거하고 동작 설명을 함께 기록한다. 최신 기능 부재를 확정하기 위해 앱 전체를 무기한 탐색하지 않고 관찰한 메뉴와 한계를 적는다.

| ID | 관찰 화면·과제 | 확보할 근거 | 현재 상태 |
|---|---|---|---|
| M01 | 저장한 플레이리스트 상세·추가·편집 | 목록과 저장 순서, 추가 위치·편집 메뉴 | 최신 기기 미확인 |
| M02 | 목록의 곡을 재생하고 미니플레이어 열기 | 진입 경로, 목록과 대기열 관계 | 미확인 |
| M03 | 전체 플레이어와 더보기 | 현재 조작·옵션·개인화 제어 후보 위치 | 미확인 |
| M04 | 대기열을 확인하고 원본 목록 편집 | 재생 중 편집과 대기열 동기화 정책 | 미확인 |
| M05 | 방금 들은 곡을 기록에서 찾기 | 경로·단위·시각·삭제/정정 메뉴 | 미확인 |
| M06 | 추천 화면·설정의 취향 제어 확인 | 추천 기준 안내·제외·초기화 메뉴 유무 | 미확인 |

관찰 환경: 일자 / 기기 / OS / 앱 버전 / 지역·구독 조건을 기록한다. 로그인 정보·결제 내역·연락처는 수집하지 않는다. 촬영·공유가 어려우면 화면을 직접 보며 경로·문구를 기록하고 캡처 미확보로 표시한다.

각 항목의 상태는 ‘직접 확인 / 공식 설명만 확인 / 관찰 범위 내 미발견 / 미확인’ 중 하나로 남긴다. 추천 패널이 변했다는 관찰과 장기 취향 모델이 변했다는 원인 추정은 분리한다.

## 3. 재현할 화면 범위 — 설계안

실제 앱 관찰을 마친 확정표가 아니라 공통 기반 설계의 초기 범위다. 미확인 화면은 제안에 맞게 재구성했다고 밝힌다.

| 화면 | 현재 자산 | 통합 목업에서 필요한 변화 | 제외할 복제 범위 |
|---|---|---|---|
| 플레이리스트 상세·편집 | 구간 삽입·블록 편집 데모 | 편집 규칙 유지, 재생·대기열 연결 | 대규모 음악서랍·폴더 관리 재구축 |
| 미니플레이어 | 재생 상태 시연 | 공통 재생 상태·전체 플레이어 진입·반영 상태 | 차량·기기 연결 |
| 전체 플레이어 | 신규 화면 필요 | 재생 셸과 한 번 탭하는 청취 설정 진입점 | 가사·EQ·다운로드·DRM |
| 대기열 | 기본 상태 시연 | 목록에서 생성·현재 재생 항목 표시·독립성 | 고급 자동재생 정책 |
| 청취 설정 시트 | Sheet 재사용 후보 | V1 토글→V2 맥락→V3 강도 점진적 노출 | 모든 설정의 첫 화면 상시 노출 |
| 청취 기록 | 미구현 | 구간·맥락·반영 상태 표시, V3 세션 정정 | 실제 멜론 계정 이력 수집 |
| 최소 추천 영역 | 미구현 | 같은 이벤트·정책에 따른 규칙 점수·순위·이유 | 실제 추천 API·전체 홈 피드 |

## 4. 관찰 후 확정할 결정

1. 플레이어에서 추가 설정이 기존 조작과 충돌하지 않는 위치는 어디인가?
2. 청취 이력과 취향 반영 상태를 같은 기록에서 보여줄 수 있는가?
3. 실제 대기열 정책과 목업 정책의 차이를 어디에 설명할 것인가?
4. 기준판은 실제 UI에서 확인된 동작과 비교용 가정을 어떻게 구분할 것인가?
5. 반영 대상과 추천 기준을 처음에는 숨기고 필요할 때 드러내도 사용자가 찾을 수 있는가?

관찰이 끝나면 화면 범위 표의 상태와 근거를 갱신한다. 그전에도 공통 데이터 계약의 설계 초안은 가능하지만, 최신 멜론의 정확한 재현으로 고정하지 않는다. 실제 사용자 검증·경쟁 서비스 우월성·추천 효과는 아직 입증하지 않았다.
