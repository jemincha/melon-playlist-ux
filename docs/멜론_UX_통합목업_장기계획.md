# 멜론 UX 통합 목업 실행계획

작성일: 2026-11-05 · 개정일: 2026-11-06
상태: 계획 수립 / 공통 기반·V1〜V3 신규 구현 및 사용자 검증 미실시

## 1. 최종 목표와 실행 원칙

**기존 편집 기능, 플레이어·대기열, 취향 반영 일시중지, 맥락별 취향·추천, 과거 세션 정정·반영 강도가 하나의 데이터와 사용 흐름으로 작동하는 목업을 완성한다.**

진행 순서는 동결 → 관찰 → 공통 기반 설계 → 편집·재생 연결 → V1 → V2 → V3 → 통합 점검·패키징이다. V2·V3 구현은 최종 범위에 포함한다. 게이트는 구현 여부가 아니라 화면·선택지·자동화의 깊이를 결정한다. 이전 V1 한정·6~8주 계획은 대체한다.

모든 단계는 기존 동작을 보존한 시연 가능한 통합 버전으로 끝낸다. 일정이 지연되면 그 시점의 누적 버전을 포트폴리오에 제시할 수 있지만, 이를 모든 기능이 완성된 최종 목업이라고 부르지 않는다.

결과물은 ‘개발자가 검토할 수 있는 명세 + 작동 목업’이다. ‘실제 멜론에 바로 이식 가능’, ‘실제 추천 정확도 개선’, ‘업계 최초’로 소개하지 않는다. 내부 앱·API·추천 파이프라인은 확인되지 않았다.

## 2. 기존 편집 데모 동결과 재사용

현재 편집 데모는 224곡 예제로 구간 삽입, 블록 전체·내부 곡 편집, 저장·취소·최근 변경 1회 복원을 제공한다. 코치마크·모바일·키보드 확인 및 로직 테스트 19개 통과 기록이 있다. 구현 검증이며 사용자 필요·효과 검증 완료는 아니다. 이번 문서 개정에서 실행 테스트를 다시 수행하지 않았다.

- 편집 기준 커밋은 v1-editing 태그로 보존하고, 이후 통합 버전에서 편집→재생→대기열 연결을 구현한다. 동결은 기존 코드의 재사용·연결까지 금지한다는 뜻이 아니다.
- 편집 기능의 장기 저장·복원이나 무관한 리팩터링을 독립 단계로 추가하지 않는다. 기존 규칙과 시연 경로를 보존한다.
- 중대한 데이터 손실·접근성 결함은 예외적으로 수정하고 근거를 남긴다.
- 현재 메모리 기반 편집과 새로고침 초기화의 한계는 명시한다. 청취 기록·정정에 필요한 최소 저장은 별도 범위다.

2026-11-06 직전 확인 기록: 로컬 HEAD 3f39b03, 로컬 태그 없음, 미커밋·미추적 파일 존재. GitHub 기본 브랜치 README에는 새 계획 연결이 없고 계획 파일 조회는 404였다. 이 개정에서 원격 상태를 다시 확인하지 않았다.

동결 완료 기준은 변경 파일 검토 → 의도한 범위만 커밋 → 편집 기준 커밋에 태그 부여 → 원격 파일·태그 확인이다. 미검토 파일을 일괄 추가하거나 기존 태그를 덮어쓰지 않는다. 2026-11-06 후속 실행: 기존 소스의 테스트 19개·린트·빌드를 재확인하고 로컬 v1-editing 태그를 생성했다. 원격 게시 상태는 실제 Git 참조 조회로 확인한다. 상세 근거는 [편집 데모 동결 기록](편집데모_동결기록.md)에 남긴다.

기존 근거: [README](../README.md), [모바일 현행조사](멜론_모바일_현행조사.md), [편집 사례 발전계획](포트폴리오_발전계획.md), [사용자 조사 기록지](사용자_조사_및_서비스_확인.md).

## 3. 일정·단계별 완료 기준

활동 주차 기준 약 14~18주를 계획 예산으로 둔다. 기반·연결 3~4주, V1·V2·V3 각 2~3주, 통합·패키징 2~3주에 동결·관찰과 단계별 검증 여유를 배분한다. 실측 납기나 성과가 아니며 병행 작업·자료 확보에 따라 달력상 기간은 달라질 수 있다. 아래 주차는 18주 배치 예시이고 검증은 각 기능 기간에 포함한다.

| 순서 | 예시 주차 | 핵심 산출물 | 시연 가능한 완료 상태 |
|---|---|---|---|
| 0. 동결 | 1주 일부 | 편집 기준 커밋·태그·원격 확인 | 돌아갈 수 있는 기존 편집 데모 |
| 1. 관찰 | 1~2주 | 실제 앱 경로·경쟁 기능·재현 화면 범위 표 | 기존 데모 유지, 새 화면의 확인/재구성 범위 확정 |
| 2. 공통 기반 | 3~4주 | 미니·전체 플레이어 셸, 이벤트·프로필 계약, 규칙 추천 골격, 기준판/개선판 | 선택→모의 재생→이벤트→기본 추천을 같은 상태로 체험 |
| 3. 편집 연결 | 5~6주 | 기존 플레이리스트→재생→대기열 연결 | 편집한 순서로 대기열 생성·재생, 이후 편집과 대기열의 독립 유지 |
| 4. V1 | 7~9주 | 일시중지·자동 종료·기록 보존 + 소규모 검증 | 청취는 기록되고 지정 구간은 취향 학습에서 제외 |
| 5. V2 | 10~12주 | 인적·활동 맥락별 취향·추천 + 소규모 검증 | 반영 대상과 추천 기준을 독립 선택하고 V1과 함께 작동 |
| 6. V3 | 13~15주 | 과거 세션 정정·반영 강도 + 소규모 검증 | 기록 정정·강도 변경이 동일 모형의 결과에 반영되고 복원 가능 |
| 7. 통합·패키징 | 16~18주 | 안내 없는 과제, 접근성·실패 복구, 최종 목업·명세·데이터 계약 | 전 기능을 한 흐름으로 시연하고 한계·근거 확인 |

단계 상한 초과 시 다음 기능을 삭제하지 않고 해당 기능의 깊이를 줄인다. 화면 장식·선택지 수·일괄 처리·고급 자동화 순으로 줄이고 핵심 데이터 일관성·오류 처리·접근성은 유지한다. 각 단계에서 실제 소요·남은 예산·축소 범위를 기록한다. 최소 완료선도 미달이면 중간 버전임을 표시하고 미해결 항목과 일정을 다시 산정한다.

## 4. 관찰과 화면 범위

멜론의 목록→재생→대기열→청취 기록→추천 경로와 개인화 제어 진입점을 같은 OS·앱 버전에서 확인한다. Spotify·Apple Music·YouTube Music도 같은 질문으로 재확인한다. 이번 문서 개정에서는 현행 기능을 새로 조사하지 않았다.

재현 범위는 저장 목록·미니/전체 플레이어·대기열·청취 기록·최소 추천 영역이다. 전체 앱 복제가 아니다. 확인되지 않은 화면 배치는 재구성으로 표시한다.

관찰표에는 일자·OS·앱 버전·지역/요금제 조건, 개인정보를 제거한 캡처·공식 링크, 기록 보존·반영 대상·과거/향후 적용·복귀·진입 경로·미확인 항목을 담는다. 기능 상태는 ‘확인됨 / 관찰 범위 내 미발견 / 미확인’으로 구분하며 미발견을 부재로 단정하지 않는다.

차별점은 ‘기록 보존과 학습 반영의 분리를 플레이어·기록 흐름에서 얼마나 자연스럽게 제어할 수 있는가’라는 검증 가설이다. 관찰 전 우월성을 주장하지 않는다. 운전 맥락은 출발 전 설정으로 검증하며 주행 중 조작을 요구하지 않는다.

## 5. 공통 기반에서 확정할 데이터 계약

기반 단계에서 아래 의미와 경계부터 정하고 실제 기능은 V1〜V3 순서로 활성화한다. 미래 기능을 위한 범용 프레임워크나 독립 대형 모델을 미리 만들지 않는다. 필드 예약이 향후 변경을 완전히 없앤다고 약속하지 않고, 변경 시 버전·호환 규칙을 명시한다.

| 개념 | 최소 계약 | 불변 조건 |
|---|---|---|
| 카탈로그·목록 | 곡 ID, 목록 ID, 저장 순서·편집 임시본 | 보기 정렬·편집 취소가 원본을 변형하지 않음 |
| 재생·대기열 | 대기열 항목 ID, 곡 ID, 현재 위치·재생 상태 | 재생 시작 시 목록 스냅샷. 이후 편집이 대기열을 암묵적으로 재배열하지 않음 |
| 청취 맥락 | 인적 태그와 활동 태그, 미지정 허용 | 혼자=기본 취향으로 단정하지 않음. 자동 상황 추정 없음 |
| 반영 대상 | learningTargetId: 기본 프로필 / 맥락 프로필 ID / 없음 | 어느 취향을 학습시키는지 표현. 없음은 기록 삭제·싫어요가 아님 |
| 추천 기준 | recommendationBasisId: 기본 / 선택 맥락 프로필 ID | 지금 어떤 취향으로 순위를 계산하는지 표현. 반영 대상과 독립 |
| 청취 이벤트 | eventId, sessionId, 곡·대기열 항목 ID, 시작·종료·청취 시간, 당시 맥락·반영 대상·반영 강도·정책 버전 | 발생 당시 값 보존, 중복 이벤트 배제 |
| 세션 정책 | 현재 맥락·반영 대상·추천 기준, 만료 시각·복귀 대상 | 정책 변경 시 새 구간 시작. 오래된 타이머가 새 정책을 덮어쓰지 않음 |
| 정정 | 이벤트/세션 범위, 이전·이후 값, 정정 ID·버전 | 원본 이벤트 보존, 적용·취소·재시도 결과 일관성 |
| 추천 결과 | 초기 이력·정정·정책·가중치 버전, 선택 기준, 점수·순위·이유 | 같은 입력이면 재현 가능, 기준판/개선판 데이터 격리 |

추천 기준은 세션 상태에 두고 추천 요청·결과에 스냅샷을 남긴다. 청취 이벤트에 보조적으로 남기더라도 반영 대상의 별칭으로 사용하지 않는다. 기존의 learn 불리언만을 원천으로 쓰지 않고, V1에서는 반영 대상이 없음인지에 따라 반영 여부를 도출한다.

V1은 기본 프로필↔없음만 사용하고 추천 기준은 기본으로 유지한다. V2는 같은 계약의 맥락 프로필을 활성화한다. V3는 원본 위 정정과 반영 강도를 적용한 유효 입력으로 재계산한다. 기본 프로필과 혼자 맥락은 별개다. 세부 규칙은 [맥락·정정 설계 메모](멜론_UX_후속구상.md)에 정리한다.

### 규칙 추천과 비교 구조

고정 가상 카탈로그·초기 이력·설명 가능한 점수 규칙으로 시작한다. 음원 없는 모의 재생과 가상 추천임을 명시한다. 목록 추가나 클릭만으로 청취 완료를 생성하지 않는다. 국내밴드 중심 224곡과 별도로 추천 비교용 가상 데이터를 준비한다.

기준판/개선판은 동일한 초기 이력·시간·재생 입력을 복제해 별도 상태에서 실행한다. 기준판의 정책은 비교용 가정으로 표시하고 실제 멜론 내부 로직이라고 부르지 않는다. 학습 제외는 점수 기여 0으로 검증한다. 토글 클릭 자체로 준비된 결과 배열을 바꾸지 않는다. 점수가 달라도 상위 곡이 같을 수 있으므로 모든 입력에서 목록 변화가 생긴다고 약속하지 않는다.

## 6. V1〜V3 최소 완료선과 깊이 조정

| 단계 | 반드시 구현할 최소 완료선 | 깊이를 줄일 수 있는 부분 |
|---|---|---|
| V1 | 플레이어 진입 토글, 유한한 자동 종료·수동 복귀, 구간별 기록 보존·학습 제외, 동일 청취 비교 | 시간 선택 개수·설명 애니메이션·코치마크 길이 |
| V2 | 인적·활동 두 축의 작은 고정 선택지, 맥락별 프로필, 반영 대상과 추천 기준의 독립 변경, 기록 없는 맥락 대체 안내 | 맥락 종류 수·사용자 정의·조합별 고급 보정. 각 축에 미지정과 최소 두 개의 지정 선택지는 유지 |
| V3 | 지난 세션 1개를 골라 반영 대상·강도 정정, 미리보기·적용·취소/복원, 변경 후 재계산. 신규 청취에도 반영 강도 적용 | 임의 시간 범위·대량 정정·연속 슬라이더·정교한 추천 반응 제어 |

V3 강도는 반영 안 함 / 적게 / 보통 등 소수 단계로 시작한다. 목업 수치는 설명 가능한 고정 규칙이며 최적값이나 실측 선호가 아니다. 원본 기록을 지우지 않고 정정을 적용한 유효 이벤트로 프로필을 재계산한다. 실제 운영 ML의 즉각적인 역학습을 약속하지 않는다.

## 7. 점진적 노출과 공통 진입점

플레이어에는 현재 상태를 짧게 표시하고 한 번의 탭으로 청취 설정 시트를 연다. V1에서 사용하는 진입점을 V2·V3에서도 유지한다.

- 기본 화면: 반영 중/일시중지 상태와 핵심 토글.
- 필요할 때 펼치는 맥락 설정: 함께 듣는 사람·활동. 선택 맥락을 반영 대상·추천 기준으로 함께 적용하는 간편 경로를 제공하되 각각 따로 바꿀 수 있다.
- 고급 설정: 반영 대상, 추천 기준, 반영 강도, 종료 시점을 명확한 문구로 구분한다. 처음부터 모두 노출하지 않는다.
- 과거 정정: 같은 시트에서 기록 보기로 연결하고 기록에서 세션을 선택한다. 깊은 정정 화면을 플레이어에 모두 넣지 않는다.

소수 선택지에서 시작하며 별도 계정처럼 보이는 페르소나 화면을 먼저 만들지 않는다. 강도와 추천 기준을 혼동한다면 이름·배치·선택지 수를 줄이고 핵심 독립성은 유지한다.

## 8. 상태·저장·실패 정책

- 곡 도중 정책·맥락·강도가 바뀌면 시각 기준으로 구간을 나누고 한 재생을 중복 집계하지 않는다.
- 만료는 절대 시각 기준으로 처리한다. V1은 기본 반영으로 복귀하고, V2 이후는 시작 직전 반영 정책으로 복귀한다. 추천 기준은 별도 명시 변경이 없으면 유지한다.
- 수동 정책 변경은 이전 종료 예약을 취소·교체한다. 백그라운드·재진입 후 만료 여부를 재평가하고 종료 중 청취를 꾸며내지 않는다.
- 청취 이력·정책·정정의 최소 로컬 저장과 버전·초기화·실패 안내를 구현한다. 편집 목록 장기 저장이나 서버 동기화로 확장하지 않는다.
- 저장 실패는 성공으로 표시하지 않고 마지막 정상본을 보호한다. 정정 실패 시 이전 유효 프로필과 기록을 유지한다.
- 반영 제외 중 좋아요의 학습 등 새 정책을 암묵적으로 추가하지 않는다. 미구현 조작은 동작하는 것처럼 보이지 않게 한다.
- 단일 브라우저·활성 탭 기준이다. 다중 기기·DRM·인증·실제 추천 API·그룹 추천·자동 상황 감지는 최종 목업 밖이다.

## 9. 단계별 검증과 깊이 게이트

각 기능 단계에서 기술 검증과 소규모 사용자 관찰을 수행한다. 참여자 수는 모집·시간에 맞게 사전에 정하고 실제 수를 기록한다. 5~8명은 모집 목표로 참고할 수 있으며 이미 확보한 참여자나 시장 대표 표본이 아니다.

| 단계 | 안내 없는 과제와 관찰 질문 | 깊이 조정 기준 |
|---|---|---|
| V1 | 가족 이동 전 설정→기록 확인→복귀. 기록 보존과 학습 제외를 구분하는가? | 오해·복귀 누락이면 문구·시간 선택을 단순화 |
| V2 | 가족+이동에서 혼자+운동으로 전환. 반영 대상과 추천 기준을 따로 설명·선택하는가? | 혼동하면 맥락 종류·고급 보정 축소, 독립 제어는 유지 |
| V3 | 지난 세션의 잘못된 반영을 찾아 수정·복원. 앞으로의 강도 변경과 과거 정정을 구분하는가? | 어려우면 세션 단위·단계형 강도만 유지 |
| 통합 | 목록 편집→재생→일시중지→맥락 전환→과거 정정→추천 확인 | 단계 사이 상태 누출·설정 망각·초점·복구 문제 우선 수정 |

관찰 기록은 익명 ID·조건·최근 실제 사례·성공/도움/실패·의미 이해·전환 누락·통제감과 이유·수정점으로 남긴다. 첫 과제에는 코치마크를 노출하지 않고 이후 설명용 시연을 분리한다. 한 번의 과제로 장기 기억이나 추천 품질 향상을 입증하지 않는다.

게이트 결정문은 ‘관찰 사실 → 반례·한계 → 유지할 최소선 → 줄일 깊이 → 다음 통합 시연’ 한 단락으로 쓴다. 게이트에서 V2·V3 자체를 삭제하지 않는다. 심각한 결함으로 진행이 불가능하면 완료로 포장하지 않고 복구·재계획한다.

공통 기술 기준: 기존 편집 회귀, 대기열 독립성, 제외 입력 기여 0, 맥락 간 반영 격리, 정정 재적용의 일관성, 강도 0·기록 없음 처리, 만료 경계·재진입·저장 실패, 키보드·터치·초점·상태 읽기·작은 화면을 확인한다. 새 로직에 맞는 테스트·린트·빌드와 브라우저 통합 경로 검증을 각 단계에서 수행한다.

## 10. 통합 시연과 패키징 완료선

최종 시연: 기존 목록에 곡을 원하는 구간으로 추가 → 편집 순서로 재생·대기열 확인 → 일시중지로 기록만 보존 → 인적·활동 맥락을 바꿔 별도 취향으로 반영 → 추천 기준 변경 → 지난 세션의 대상·강도 정정 → 결과 확인·복원.

필수 산출물은 누적 통합 목업, 화면·상태 명세, 이벤트·프로필·정정 데이터 계약, 규칙 추천의 입력·출력 설명, 단계별 관찰·깊이 결정, 한계·복구 안내, 멜론 포폴·README·짧은 시연이다. PPT·Brunch 글은 목적에 맞게 별도 제작하며 외부 게시와 구분한다.

기존 편집과 취향 제어는 한 앱 경험으로 연결하되 각 문제의 근거·검증 결과를 합치지 않는다. 새 화면의 캡처·대체 텍스트·구현 범위·테스트 수를 함께 갱신한다. 실제 사용자 관찰, 가상 추천 모형, 실제 서비스 효과를 구분한다. 단일 진입점에서 시연·근거에 접근하게 하고 공개 URL은 실제 게시·확인 후에만 적는다. 공개 배포·최종 제출은 별도 요청에 따라 실행한다.
