# 모바일 적용안 구현 검증

> 확인일: 2026-10-10
> 대상: 로컬 React 데모. 실제 멜론 앱의 사용성 결과가 아니다.

## 자동 검증

- 운영 빌드 성공.
- 로직 테스트 19건 통과: 기존 13건과 신규 6건.
- lint 경고 없이 통과.
- 새 테스트는 보기 정렬의 원본 보존, 분산된 모든 아티스트 구간 제공, 사용자가 선택한 작은 구간에 삽입, 처음/끝 추가, 중복·잘못된 위치 방어, 블록·단일 곡 이동 시 곡 보존을 검증한다.

## 브라우저 직접 확인

| 확인 항목 | 확인 결과 |
|---|---|
| 기본 목록 | 224개 행이 표시되고 앨범 이니셜 이미지가 정상 로드됨 |
| 한로로 가상 신곡 삽입 | 13곡이 있는 204~216번째 구간을 선택, 이상비행과 다음 곡 사이에 삽입 |
| 곡 누락·중복 | 삽입 후 225개 행·225개 고유 ID |
| 기존 곡 순서 | 신곡을 제외한 모든 ID의 상대 순서가 추가 전과 동일 |
| 추가 되돌리기 | 원래 224곡 ID 순서와 동일하게 복원 |
| 묶음 이동 | 첫 3곡 묶음을 다음 묶음 아래로 이동, 224개 행 유지 |
| 편집 취소 | 임시 이동을 저장하지 않고 원래 순서 복원 |
| 편집 저장·되돌리기 | 이동 순서 저장 후 이전 순서 복원 |
| 아티스트 정렬 보기 | 전체 224곡 유지, 편집 진입 시 저장된 순서로 복귀 |
| 기본 모형 경계 | 묶음 스위치·제안 정렬 조작이 기본 모형에 없음 |
| 키보드 묶음 이동 | Enter로 잡기 → ArrowDown → Enter로 놓기, 첫 3곡 묶음이 다음 묶음 뒤로 이동 |
| 모달 키보드 | Escape로 닫기 확인, 네이티브 dialog의 포커스 관리 사용 |
| 모바일 폭 | 390×844 viewport에서 페이지 가로 넘침 없음 |
| 브라우저 로그 | 확인 시 오류·경고 없음 |

묶음 내부의 개별 곡을 비활성 sortable로 등록했을 때 키보드 이동 대상이 개별 곡으로 잡히는 문제를 발견했다. 묶음 모드에서는 내부 행을 일반 행으로 렌더링해 묶음만 이동 대상으로 등록하도록 수정하고 다시 확인했다.
