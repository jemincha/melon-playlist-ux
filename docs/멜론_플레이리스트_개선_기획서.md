# 멜론 플레이리스트 편집 UX 개선 프로토타입 기획서

작성: 2026-08-31 · 구현 대조 및 근거 정리: 2026-10-09

## 누구의 어떤 문제인가

수백 곡의 플레이리스트를 직접 정리하며 아티스트별 구간과 곡 순서를 유지하는 사용자에게, 신곡을 목록 끝에서 원하는 구간까지 옮기는 일이 반복되는 문제다. 제작자의 10년 실사용 경험에서 발견한 가설이며 실제 목록에서 추출한 224곡 데이터로 재현한다. 한 사람의 경험과 한 목록은 사용자 전체를 대표하지 않는다.

## 왜 이 문제를 선택했는가

문화 콘텐츠 서비스의 개선을 구체적인 조작 과제로 구현할 수 있고, 프론트 단독 프로토타입으로 기존 순서 보존 여부를 확인할 수 있어 선택했다. 가격 정책·제휴·브랜드 전략은 이 MVP의 검증 범위에서 제외했다. 구현 가능성은 선택 이유 중 하나이며 사용자 수요의 증거는 아니다.

## 어떤 가치를 검증하려는가

전체 목록을 다시 정렬하지 않고 새 곡 하나만 원하는 구간으로 옮겨, 사용자가 만든 나머지 순서를 유지하고 정리 비용을 줄인다는 가설이다. 시간 절약 수치, 이용 빈도, 만족도는 아직 측정하지 않았다.

## 경쟁사 자료로 확인한 것과 확인하지 못한 것

공식 웹 문서 확인일: 2026-10-09. 로그인된 앱 조작이나 앱 버전별 비교는 수행하지 않았다.

| 자료 | 확인된 범위 | 이 자료만으로 결론낼 수 없는 것 |
|---|---|---|
| [Spotify Sort and filter](https://support.spotify.com/us/article/sort-and-filter/) | 플레이리스트 검색과 열 기준 정렬 등을 안내한다. | 원하는 구간으로 신곡만 삽입하는 기능의 전체 플랫폼 부재 |
| [Skiley 공식 사이트](https://skiley.net/) | 플레이리스트 관리·정렬 도구를 제공한다고 안내한다. | 본 프로젝트와 같은 문제의 규모·빈도 또는 특정 사용자 수요 |
| 멜론 실사용 경험 | 제작자가 곡을 직접 옮기며 겪은 불편 | 최신 앱의 정확한 동작·옵션 및 전체 사용자 경험 |

따라서 이전 문서의 ‘업계 전반의 미해결 영역’ 표현과 추적할 수 없는 인용 태그는 제거했다. 최신 멜론 확인 시 OS, 앱 버전, 날짜, 추가·순서 변경 화면을 함께 기록한다.

## 현재 MVP는 어떻게 동작하는가

1. 곡 추가 버튼은 가상 신곡을 목록 끝에 추가한다.
2. 이번 세션에 추가된 곡만 이동 후보로 판단한다. 오래된 분리 구간은 의도적 구간으로 보존한다.
3. 같은 아티스트의 기존 구간이 있으면 목적지를 선택하고 버튼 또는 드래그로 이동한다.
4. 기존 구간 바로 뒤에 붙거나, 같은 아티스트의 기존 구간이 없으면 별도 이동 후보로 분리하지 않는다.
5. 이동 후 해당 구간을 강조한다. 새로고침 시 초기 데이터로 돌아간다.

자동 삽입 기능을 완성했다고 설명하지 않는다. 현재는 사용자 실행 방식이다. 데이터는 초기 기획의 50~80곡에서 실제 224곡으로 바뀌었다. 검색·다중 선택·오프라인 상태 표시는 시연 보조 기능이다.

## 어떤 결정을 했는가

[의사결정과 검증 기록](검증_및_의사결정.md) 참고. 가장 큰 기존 구간은 기본 목적지일 뿐이다. 같은 아티스트를 서로 다른 무드 구간에 배치한 사용자는 다른 구간을 선택할 수 있다.

## 성공 기준과 다음 검증

- 기능 기준: 이동한 곡 이외의 상대 순서를 유지한다. 기존 분리 구간과 여러 추가곡을 누락하지 않는다.
- UX 기준: 기존 방식보다 완료 시간·조작 부담이 줄고, 사용자 의도와 맞는 구간에 들어간다. 아직 검증 전이다.
- 전달 기준: 설명 없이 문제와 해결을 이해하는지 확인한다. ‘3초 이해’는 입증된 결과가 아니다.
- 공개 시연: 배포 링크는 아직 없다.

목표 사용자 3~5명 대상 탐색적 비교 과제 및 기록 양식은 검증 문서에 준비했다. 실제 멜론을 쓰지 못하면 재현 화면임을 명시하고 실제 앱의 개선 효과로 일반화하지 않는다.
