# 멜론 포폴 — 실제 기술·편집 문제 기록

> 정리일: 2026-10-11. 대상은 로컬 프로토타입이다. 실제 멜론 앱의 결함이나 일반 사용자 연구 결과가 아니다.

## 1. 블록 키보드 이동 대상이 내부 곡으로 잡힌 문제

**발생 조건:** 아티스트 묶음 편집에서 내부 곡을 비활성 sortable로 등록한 상태로 키보드 묶음 이동을 실행했다.

**관찰:** 키보드 이동 대상이 묶음이 아니라 개별 곡으로 잡혔다. 이동 단위가 사용자의 블록 선택과 일치하지 않았다.

**원인:** 내부 행도 정렬 영역에 등록되어 있었다. 내부 조작을 비활성화하는 것만으로 묶음의 정렬 대상 집합에서 제외되지 않았다.

**수정 과정:**

1. 처음에는 묶음 모드의 내부 행을 일반 행으로 렌더링해, 블록만 이동 대상으로 등록했다.
2. 이후 내부 곡 편집을 추가하면서 외부 블록 이동과 각 블록 내부 곡 이동에 별도의 DnD 컨텍스트·정렬 대상 집합을 사용했다.
3. 내부 이동 콜백은 출발·도착 곡이 해당 블록에 속하는지도 확인한다. 블록 키보드 이동은 블록 대상 목록에서 위치를 계산한다.

**확인:** 초기 수정 후 키보드로 첫 3곡 묶음을 다음 묶음 뒤로 옮기고 전체 곡 수와 내부 순서를 확인했다. 내부 편집 추가 이후에는 블록과 개별 곡의 키보드 이동을 각각 확인했다. 포인터·키보드의 모든 조합을 자동화한 회귀 테스트가 있는 것은 아니다.

**근거:**

- [최초 문제 관찰과 수정 기록](모바일_적용안_검증.md): 비활성 내부 sortable가 키보드 대상으로 잡힌 관찰 포함.
- [이후 블록·내부 편집 확인](블록_편집_및_체험가이드.md).
- `src/components/MelonMobileDemo.jsx`: `ArtistSegment`, `blockKeyboardCoordinates`, `moveInside`, `dragEnd`.

## 2. 묶음 모드에서 내부 곡의 순서를 편집할 수 없던 누락

**작업:** 아티스트 곡들을 함께 옮긴 뒤, 그 안의 감상 순서도 조정한다.

**문제:** 묶음 이동만 제공하면 내부 곡 순서를 바꿀 수 없어 편집 작업이 끝나지 않는다. 기존 묶음 모드에서는 곡별 이동 조작을 숨겼다.

**원인:** ‘묶음을 옮긴다’와 ‘묶음 안을 편집한다’를 별개 작업으로 다루지 않았고, 내부 곡 이동의 범위를 정의하지 않았다.

**수정:** 제목 옆에는 블록 전체 이동, 곡 옆에는 내부 이동 조작을 배치했다. 내부 드래그는 해당 블록 안에서만 처리한다. ↑↓의 이동 후보도 해당 블록에서 찾고, 첫 곡의 위·마지막 곡의 아래 이동은 비활성화한다. 다른 아티스트 구간으로 개별 곡을 옮기는 작업은 곡별 편집에서 수행한다.

**확인:** Tuesday Beach Club 3곡의 묶음을 옮긴 뒤, Endless Shine을 Lean 위로 이동했다. 첫 곡이 된 Endless Shine의 위 이동 버튼이 비활성인지 확인하고, 저장 후 변경된 ID 순서가 목록에 반영되는지 확인했다.

**근거:**

- 개발 과정에서 사용자가 요구한 내부 순서 편집과 실제 구현·브라우저 확인 기록.
- [블록·내부 편집 확인](블록_편집_및_체험가이드.md).
- `src/components/MelonMobileDemo.jsx`: `TrackRow`, `ArtistSegment`, `stepTrack`, `moveInside`, `endEdit`.

이 사례는 확인된 기능 누락과 그 해결이다. 일반 사용자들의 오류율이나 작업 시간 감소를 측정했다는 뜻은 아니다.

## 별도 항목으로 다룰 것

- 코치마크와 단일 체험 경로: 포트폴리오 시연 구성. 위 기술 문제의 해결 근거로 혼용하지 않는다.
- 보기 정렬과 저장 순서 분리, 분리된 아티스트 구간 유지, 취소·되돌리기: 설계 원칙과 예방한 위험. 실제 순서 손실 사건이 있었다고 주장하지 않는다.
- 삽입 순서·곡 보존 등의 19개 로직 테스트: 해당 함수의 검증 근거. 드래그 센서와 UI까지 자동 검증했다는 의미로 확장하지 않는다.

새 사례는 실제 관찰과 근거가 있을 때 추가한다. 포트폴리오 분량을 채우기 위해 버그를 만들거나, 앞으로 검사할 위험을 이미 해결한 사건처럼 쓰지 않는다.
