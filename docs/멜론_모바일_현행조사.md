# 멜론 모바일 현행 기능 조사와 개선안 적용

> 조사일: 2026-10-10
> 방법: 공식 앱스토어 설명·버전 기록·홍보 화면·멜론 고객센터·공개 사용자 리뷰 확인
> 한계: Android/iOS 앱을 실제 기기에서 로그인하여 직접 조작하지 않았다. 현재 상세 목록·편집 화면의 정확한 좌표, 모든 메뉴, 동기화 정책은 미확인이다.

## 1. 조사 결론

원래 데모의 재생목록·음악서랍·믹스업 탭과 정렬 설명은 Windows 플레이어의 공식 안내와 겹친다. 이것을 현재 모바일 플레이리스트 상세 UI의 근거로 사용하지 않는다.

이번 데모는 모바일 음악서랍에 저장한 ‘국내밴드’ 플레이리스트를 편집하는 과제에 집중한다. 현재 재생할 곡의 대기열과 저장한 플레이리스트는 별개 개념으로 취급한다. 전체 플레이어를 새로 디자인하기보다 곡 목록의 편집 진입점과 추가 위치 선택에 제안 기능을 배치한다.

공개 자료로 확인되는 기존 기능을 무시하고 ‘기능이 없다’고 주장하지 않는다. 아티스트 정렬은 Windows에서 이미 확인되므로 업계 최초 또는 멜론 전체의 신규 기능으로 소개하지 않는다. 모바일 지원 여부는 직접 확인할 과제다.

## 3. 시각적으로 직접 확인한 공식 화면

iOS 스토어의 음악서랍 홍보 이미지에서 다음을 확인했다.

- 어두운 기본 배경과 흰 글자, 녹색 강조.
- 상단 음악서랍 제목과 추가·검색 아이콘.
- 플레이리스트·좋아요·많이들은·다운로드 등 바로가기.
- 최근 들은 콘텐츠와 목록 카드.
- 하단 미니플레이어의 진행 표시·곡 정보·재생 조작·목록 아이콘.

[관찰한 공식 이미지](https://is1-ssl.mzstatic.com/image/thumb/PurpleSource211/v4/63/3e/8a/633e8a31-3b68-ddca-c461-ed8613165dae/SC_04.jpg/460x996bb.webp)

해당 홍보 화면 안에는 2024년 관련 문구가 보인다. 조사일에 게시되어 있다는 사실과 캡처 시점이 최신이라는 주장은 다르다. 이 이미지에는 개인 플레이리스트 상세·순서 편집·정렬 팝업이 보이지 않는다.

## 4. UI 재현 수준과 개선안의 경계

| 요소 | 구현 방식 | 근거 수준 |
|---|---|---|
| 어두운 색상·녹색 포인트·미니플레이어 | 공식 음악서랍 이미지의 시각 언어 참고 | 공개 이미지 관찰 |
| 음악서랍에서 저장한 목록을 여는 맥락 | 단일 데모 목록을 열도록 단순화 | 공식 서비스·DJ 안내 참고, 정확한 깊이 미확인 |
| 목록 제목·커버·전체듣기·곡 추가·편집의 배치 | 관리 과제를 위한 UI 재구성 | 상세 화면의 픽셀 단위 재현 아님 |
| 처음/끝 추가 선택 | 과거 iOS 도입 기록을 바탕으로 구성 | 현재 팝업 문구·배치 미확인 |
| 기본 편집의 단일 곡 이동 | 드래그와 위/아래 버튼을 제공 | 과제 비교용 모형. 버튼은 데모의 키보드 대체 조작이며 현재 앱의 존재를 주장하지 않음 |
| 아티스트순 보기 | 원본 배열을 유지한 상태에서 표시만 정렬 | 제안 기능. 모바일 기존 지원 여부 미확인 |
| 아티스트 묶음 편집 | 편집 모드에서 명시적으로 켜는 스위치 | 제안 기능 |
| 같은 아티스트 구간에 삽입 | 모든 연속 구간을 후보로 표시하고 앞뒤 곡을 미리보기 | 제안 기능 |
| 저장·취소·되돌리기 | 임시 편집과 저장된 목록 분리, 최근 변경 1회 복원 | 제안한 상태 관리·피드백 방식 |
| 재생 상태·별도 대기열 | 음원 없이 상태만 전환, 시작 시 목록 복사 | 시연용. 실제 앱의 동기화 정책 재현 아님 |
| 앨범아트·신곡 | 이니셜 이미지와 가상 신곡 | 더미 자료. 실제 앨범 이미지·발매 정보 아님 |

첫 화면과 조사 근거 영역에 재구성임을 표시한다. ‘기본 편집 모형’을 ‘현재 멜론 완전 재현’ 또는 정량 효과 측정의 검증된 기준으로 부르지 않는다.

## 5. 이번 구현의 흐름

### 기본 편집 모형

저장 목록 → 곡 추가 → 가상 신곡 선택 → 처음/끝 선택 → 추가.
저장 목록 → 편집 → 개별 곡 이동·선택 삭제 → 완료 또는 취소.

현재 멜론의 기능 전체를 제한하거나 없다고 주장하는 비교가 아니다. 아직 미확인인 모바일 기능은 모형에 없는 것과 서비스에 없는 것을 구분한다.

### 개선안

저장 목록 → 곡 추가 → 가상 신곡 선택 → 기존 아티스트 구간을 선택 → 앞뒤 곡 미리보기 → 추가 → 되돌리기 가능.
저장 목록 → 편집 → 아티스트 묶음 켜기 → 이어진 곡 전체를 이동 → 저장 또는 취소.
저장 목록 → 아티스트순 보기 → 원본 순서 보존 → 편집 진입 시 저장된 순서로 복귀.

같은 아티스트가 여러 곳에 있으면 모두 별개 후보로 제공한다. 가장 큰 구간을 강제로 정답으로 정하지 않는다. 목록 상단으로 곡을 빼거나 ‘잘못 배치됨’ 경고를 붙이지 않는다.

## 6. 현재 상태와 남은 확인

구현과 로컬 브라우저 확인 결과는 [모바일 적용안 검증](모바일_적용안_검증.md)에 기록했다. 이 결과는 현재 멜론 앱의 기능 관찰이나 사용자 효과 측정을 대신하지 않는다.

- [x] 공개 이미지의 시각 언어를 참고한 모바일 목록 데모 구현.
- [x] 기본 모형과 제안 기능의 경계 표시.
- [ ] 실제 기기에서 현재 멜론의 저장 목록 상세·편집 화면 관찰.
- [ ] 모바일 아티스트 정렬·다중 이동의 지원 범위 확인.
- [ ] 실제 추가 위치 팝업·완료/취소·대기열 연동 정책 확인.

정확한 현행 UI 위에 기능만 추가한 최종 재현을 위해 필요한 자료는 동일 OS·앱 버전의 저장 목록 상세, 편집 진입 직후, 정렬 메뉴, 곡 담기 선택 화면이다. 개인정보를 제외한 실제 화면이 확보되면 배치·문구·아이콘과 진입 경로를 그 기준으로 맞춘다. 자료 확보 전에는 이번 결과를 ‘공개 자료 기반 적용안’으로 소개한다.
