# 플레이리스트 관리 — 사용자 조사·서비스 확인 기록지

> 작성일: 2026-10-10
> 상태: 조사 준비 / 실제 관찰·인터뷰·측정 결과 없음
> 목적: 아티스트 정렬(J1), 블록 이동(J2), 신곡 삽입(J3) 중 어떤 과제를 우선할지 결정한다.

공개 자료 조사 결과는 [현행 모바일 기능 조사](멜론_모바일_현행조사.md)에 기록했다. 아래 실제 기기 관찰·인터뷰·측정 기록은 여전히 미실시다. 공식 스토어 설명·과거 버전 기록·리뷰를 직접 조작 결과로 옮겨 적지 않는다.

## 1. 조사 진행 순서

1. 현재 멜론의 추가·정렬·편집 동작을 기록한다. 가능하면 비교 서비스에서도 같은 과제를 수행한다.
2. 직접 목록을 관리하는 사용자 약 5명의 최근 사례를 탐색한다.
3. 실제 행동을 먼저 확인한 뒤 해결 후보에 대한 반응을 확인한다.
4. J1~J3의 필요와 반례를 정리하고 다음 설계 범위를 결정한다.

아래 표의 빈칸은 미확인 상태다. 작성자가 예상하는 답이나 기존 MVP의 동작으로 채우지 않는다.

## 2. 현재 서비스 동작 확인

### 관찰 환경 — 서비스별로 복제

| 항목 | 기록 |
|---|---|
| 서비스 / 관찰일 | 미확인 |
| 앱 버전 / OS / 기기 | 미확인 |
| 계정·이용권 조건 | 미확인 — 개인정보 제외 |
| 대상 목록 규모 / 정렬 상태 | 미확인 |
| 근거 파일 또는 공식 링크 | 미확인 |
| 직접 관찰 / 도움말 확인 / 기억 기반 | 미확인 |

### 확인할 동작

| 과제 | 시도할 내용 | 실제 동작·경로·제약 | 근거 |
|---|---|---|---|
| 곡 추가 | 기본 상태에서 한 곡 추가, 다른 정렬 보기에서도 추가 | 미확인 | 미확인 |
| 아티스트 정렬 | 해당 옵션 존재·설정 경로·종료 방법 확인 | 미확인 | 미확인 |
| 보기와 감상 순서 | 정렬 전후 재생 순서, 기존 순서 복원, 재실행 후 상태 확인 | 미확인 | 미확인 |
| 단일 곡 이동 | 목록 하단의 곡을 중간의 특정 구간으로 이동 | 미확인 | 미확인 |
| 다중 곡 이동 | 연속·비연속 곡을 선택해 한 번에 이동 가능한지 확인 | 미확인 | 미확인 |
| 위치 지정 | 추가 시 위치 선택, 특정 곡 뒤 삽입, 검색으로 위치 찾기 | 미확인 | 미확인 |
| 복원 | 이동·정렬 적용을 취소하거나 기존 순서로 복원 | 미확인 | 미확인 |

옵션을 찾지 못한 경우 ‘관찰한 경로에서 찾지 못함’으로 기록한다. 지원하지 않는다고 단정하기 전 공식 안내나 다른 경로를 확인한다. 스크린샷은 필요한 영역만 남기고 계정 이름·결제 정보 등을 제외한다.

## 3. 참여자 선정

최근 한 달 안에 직접 만든 플레이리스트에 곡을 추가한 사람을 우선 찾는다. 순서를 직접 관리하는 사례를 중심으로, 목록이 작거나 순서에 관심이 적은 비교 사례도 가능하면 포함한다. 특정 의견에 동의하는 사람만 모집하지 않는다.

| 질문 | 기록할 내용 |
|---|---|
| 주로 이용하는 음악 앱은 무엇인가? | 서비스, 주 이용 기기 |
| 직접 만든 목록의 대략적인 곡 수는? | 목록 수, 대표 목록 규모 |
| 최근 곡을 추가하거나 순서를 바꾼 시점은? | 최근 사례와 빈도 |
| 목록을 보통 어떻게 듣는가? | 순서 재생·셔플·상황별 사용 |

## 4. 20~30분 탐색 인터뷰 가이드

### 시작 안내

“플레이리스트를 실제로 어떻게 관리하는지 알아보려 합니다. 앱 사용법을 평가하는 자리가 아닙니다. 답하기 어려운 질문은 건너뛰어도 되고, 개인정보가 보이는 화면은 보여주지 않아도 됩니다. 기록은 익명으로 남기겠습니다.”

녹화나 원문 인용·화면 공개가 필요하면 해당 용도를 별도로 동의받는다. 공유 가능한 화면이 없으면 말로 설명한 사례임을 기록한다.

### 최근 행동 확인 — 기능 제안 전에 질문

1. 가장 최근 곡을 추가한 목록은 어떤 목록인가요? 왜 그 곡을 넣었나요?
2. 추가한 뒤 그대로 두었나요, 위치를 바꿨나요? 실제 과정을 보여주거나 설명해 주세요.
3. 그 목록의 순서는 어떤 기준으로 만들었나요? 순서가 중요하지 않은 경우도 있나요?
4. 여러 곡을 함께 옮기거나 같은 아티스트의 곡을 모았던 최근 사례가 있나요?
5. 원하는 위치를 찾거나 옮기는 과정에서 번거로웠던 부분이 있었나요? 없었다면 무엇이 편했나요?
6. 편집을 포기하거나 나중으로 미룬 적이 있나요? 대신 무엇을 했나요?
7. 같은 아티스트의 곡을 일부러 떨어뜨려 배치한 적이 있나요? 어떤 이유였나요?
8. 현재 앱의 검색·정렬·선택 기능으로 충분히 해결되는 작업은 무엇인가요?

‘아티스트별로 묶이면 편하겠죠?’, ‘곡이 많아서 힘들지 않나요?’처럼 해결책과 불편을 먼저 제시하지 않는다. 기억이 모호하면 구체적인 사례를 확인할 수 없었다고 기록한다.

### 해결 후보 반응 — 행동 확인 뒤에 진행

아티스트 기준 정렬, 여러 곡의 묶음 이동, 새 곡의 삽입 위치 선택을 각각 설명한다. 가능하면 제시 순서를 바꾼다.

- 최근에 설명한 작업 중 어디에 쓸 수 있나요? 쓸 일이 없다면 이유는 무엇인가요?
- 정렬은 화면에서 보기만 바뀌길 원하나요, 실제 감상 순서도 바뀌길 원하나요?
- 같은 아티스트 구간이 여러 곳이면 어느 곳을 선택할까요? 선택 전에 무엇을 보고 싶나요?
- 자동으로 위치가 바뀐다면 어떤 경우에 원하지 않을까요?

‘좋아 보인다’는 반응과 실제로 반복되는 필요를 따로 기록한다. 기존 MVP를 보여줬다면 노출 시점과 설명 내용을 남긴다.

결정 선택지는 ‘진행 / 대상 축소 / 해결책 전환 / 보류’다. 소규모 조사이므로 다수결이나 시장 비율로 해석하지 않는다. 반복되는 구체적 사례, 기존 대안의 한계, 사용자의 의도를 보존할 수 있는지를 함께 판단한다. 조사 전 기능 선호 순위는 없다.

## 7. 후속 사용성 비교 기록 양식

설계가 확정된 뒤 사용한다. 기존 방식이 기억 기반 모형이면 그 사실을 결과에 명시한다.

### 테스트 전에 고정할 조건

- 선정 과제와 데이터: 미정. J1~J3 조사 결과에 따라 결정.
- 시작 조건: 안내를 읽고 시작을 누른 시점. 초기 목록·보기·목표는 두 조건에서 동일.
- 완료 조건: 목표 순서 또는 위치가 적용되고 참여자가 완료를 선언한 시점.
- 실패 조건·제한 시간: 테스트 전에 지정하고 모든 참여자에게 동일하게 적용.
- 비교 순서: 기존→개선 / 개선→기존을 번갈아 배치.
- 도움·연습·입력 방식: 조건을 동일하게 하고 실제 개입을 기록.
- 추천 적합성: 목표를 지정하는 효율 과제와 별개로 자유 위치 선택 과제를 수행.

| ID | 과제 | 방식·체험 순서 | 시간 | 완료/실패 | 오류·도움 요청 | 위치 이해·복원 | 의견 |
|---|---|---|---|---|---|---|---|
| 미실시 | 미정 | 미정 | 미측정 | 미측정 | 미측정 | 미측정 | 미실시 |

공통 반례: 동일 아티스트 구간 여러 개, 신규 아티스트, 복수 곡 이동, 의도적인 분산 배치, 추천 거절, 실행 취소. 기능 범위에 맞게 선택한다. 시간 개선율을 계산할 경우 실패를 제외했다는 사실을 숨기지 않고, 원자료와 계산 조건을 함께 제시한다.
