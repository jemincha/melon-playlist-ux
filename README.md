# 멜론 플레이리스트 편집 UX 개선 프로토타입

10년간 멜론을 사용하며 발견한 플레이리스트 정리 문제를 React로 재현하고, 신곡을 기존 아티스트 구간으로 옮기는 대안을 구현한 개인 프로젝트다. 실제 멜론 서비스와 무관한 비공식 UI 시뮬레이션이다.

## 어떤 문제를 해결하는가

대상은 수백 곡의 플레이리스트를 직접 정리하고, 아티스트별 구간과 곡 순서에 의미를 부여하는 사용자다. 신곡이 목록 끝에 추가되면 기존 구간을 찾아 이동해야 한다. 목표는 **이동할 곡 이외의 상대 순서를 유지하면서 신곡 정리 비용을 줄이는 것**이다.

문제의 출발점은 제작자의 개인 경험과 실제 플레이리스트에서 추출한 224곡 데이터다. 여러 사용자에게 반복되는 문제인지, 얼마나 시간을 절약하는지는 아직 검증하지 않았다. 경쟁사의 기능 부재나 업계 전체 수요를 단정하지 않는다.

## 핵심 시나리오와 데모

1. `곡 추가 시뮬레이션`에서 가상 신곡을 추가한다. 곡은 먼저 목록 끝에 붙는다.
2. `As-Is / To-Be 비교 보기`로 원래 위치와 가장 큰 기존 구간으로 이동한 미리보기를 확인한다.
3. 이동 후보 카드에서 목적지를 고르고 `블록으로 이동`을 누르거나, 같은 아티스트 구간에 드롭한다.
4. 해당 구간으로 스크롤되고 하이라이트된다. 나머지 곡들의 상대 순서는 유지된다.

기존에 같은 아티스트를 여러 구간으로 나누어 둔 경우도 모두 유지한다. 이번 세션에서 추가한 곡만 이동 후보가 될 수 있다. 기존 구간 바로 옆에 붙은 신곡과 처음 등장한 아티스트는 별도 이동 후보로 표시하지 않는다.

## 구현 범위

| 범위 | 구현 |
|---|---|
| 핵심 개선 | 연속된 아티스트 구간 표시, 신곡 추가, 목적지 선택, 버튼·드래그 이동 |
| 편집 | 블록 재정렬, 같은 블록 내부 트랙 재정렬, 다중 선택·일괄 삭제 |
| 시연 보조 | 상하 비교뷰, 자동 스크롤·하이라이트, 검색, 메타정보 패널, 오프라인 상태 표시 |
| 데이터 | 실제 목록에서 정제한 224곡 + 가상 신곡 5개, 세션 내 React 상태 |
| 제외 | 로그인, 멜론 API, 실제 음원 재생·다운로드, 서버 저장 |

아티스트 가나다순은 표시 방식이다. 이 상태에서는 순서 편집을 막아 기본순이 뜻하지 않게 덮어써지는 일을 방지한다. 검색 중에도 순서 편집 대신 검색 결과 목록을 표시한다.

## 주요 결정과 한계

- 전체 아티스트순 정렬 대신 **연속 구간**을 사용해 기존 커스텀 순서를 보존한다.
- 추가 직후 자동 이동하지 않는다. 사용자가 목적지와 실행 여부를 결정한다.
- 기본 목적지는 가장 큰 기존 구간이며 동점이면 먼저 나온 구간이다. 이 규칙은 편의상 정한 기본값으로, 사용자 선호를 검증한 결과가 아니다. 다른 구간도 선택할 수 있다.
- 아티스트명 문자열이 정확히 같을 때만 매칭한다. 동명이인·공동 아티스트·표기 차이는 해결하지 않았다.
- 비교뷰는 첫 이동 후보에 대한 기본 목적지 미리보기다. 카드에서 고른 다른 목적지와 연동되지 않는다.
- 새로고침하면 편집 결과가 초기화된다. 오프라인 토글은 다운로드 상태를 해시로 모사하며 실제 오프라인 재생을 제공하지 않는다.

## 실행과 검증

React 19 + Vite, dnd-kit, Node.js 내장 `node:test`를 사용한다. 백엔드는 없다.

```bash
npm ci
npm run dev
```

```bash
npm test
npm run build
npm run lint
```

2026-10-09 코드 개선 후 순수 함수 테스트 18개 통과. 기존 분리 구간 유지, 여러 신곡 후보, 특정 구간 삽입, 잘못된 목적지 거부, 나머지 곡 순서와 원본 불변성을 확인한다. UI 검증 결과와 환경은 [검증 기록](docs/검증_및_의사결정.md)에 분리해 남긴다. 테스트 통과를 UX 효과로 해석하지 않는다.

## 다음 개선

1. 최신 멜론 앱 버전·화면에서 기존 정리 과제를 확인한다.
2. 목표 사용자 3~5명에게 기존 방식과 MVP의 동일 과제를 수행하게 하고 시간·조작 수·실패·목적지 선택을 기록한다.
3. 측정 결과에 따라 기본 목적지, 이동 안내, 실행 취소의 필요성을 판단한다.
4. 공개 배포 링크를 추가한다.
